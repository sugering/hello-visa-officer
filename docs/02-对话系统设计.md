# 对话系统设计

> 数据驱动的对话树 + 数值化的"糊弄"策略。核心目标：**每一句话都有代价，且代价在选择前可预判**。

## 1. 三层结构

```
scenario.json   场景：回合上限、起始怀疑度、终局阈值、起始材料
   └─ dialogue.json  节点(node)：谁在说、说什么、有哪些选项
        └─ option    选项：说什么、要什么条件、造成什么后果、跳到哪
```

引擎实现见 `prototype/engine.py`（`Node` / `Option` / `Interview`），内容见 `prototype/content/`。

## 2. 节点字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `speaker` | `officer` / `narrator` | 说话人 |
| `text` | string | 台词，**单个节点不超过 60 字** |
| `mood` | string? | 可选。强制本节点立绘表情；不写则由怀疑度分档决定（**推荐不写**） |
| `options` | array | 2–3 个选项（4 个以上玩家会开始乱点） |
| `puzzle` | string? | 进入本节点时弹出解谜（如 `seal_align`） |
| `terminal` | bool | 裁决节点；选项 `goto: null` 时结算结局 |
| `on_enter` | object | 进入时立即生效的 `effects`（设置 flag、扣怀疑度等） |

## 3. 选项字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定标识，**存档与测试都靠它，改名等于坏档** |
| `text` | string | 玩家看到的话（第一人称动作或台词），≤ 30 字 |
| `requires` | object | 可用条件，不满足则置灰（引擎返回 `locked` + `reason`） |
| `effects` | object | 后果，见下表 |
| `goto` | string \| object \| null | 下一节点；`{hold, break, default}` 按追问结果分支；`null` 代表谈完了 |
| `tags` | array | `social` / `silent` / `humor` / `bluff` / `risk`，用于统计与成就 |

### 3.1 requires

| key | 含义 |
|---|---|
| `materials: [id]` | 必须持有这些材料（已被击穿/消耗的不算） |
| `flags: [name]` | 必须已有这些 flag |
| `not_flags: [name]` | 不能有这些 flag（用过一次的招不能再使） |
| `max_suspicion: n` | 怀疑度高于 n 时此选项失效（"他已经不听你解释了"） |

### 3.2 effects（完整表）

| key | 效果 |
|---|---|
| `suspicion: ±n` | 怀疑度增减 |
| `statements: ["purpose:conference"]` | 玩家做出陈述；**会与已读材料事实做矛盾比对**，冲突则 +20 怀疑度并标记 `caught_lying` |
| `submit: [id]` | 递交材料：进入评分、材料事实被签证官读到、可消耗材料被消耗 |
| `consume: [id]` | 仅消耗不递交 |
| `grant: [id]` | 获得材料（解谜奖励等） |
| `remove_flaws: ["bank_statement:存款日期集中"]` | 修补材料破绽，同时 +12 抗性 |
| `probe: id` | 让签证官就这份材料追问，结果 `hold` / `break` 决定 `goto` 分支 |
| `intrigue: true` | 立绘切「突然感兴趣」 |
| `flags` / `not_flags` | 置位 / 清除标记 |

### 3.3 goto 分支

```json
"goto": { "hold": "q_ties", "break": "q_funds_probe", "default": "q_ties" }
```

- `hold`：材料扛住了追问 —— 你赢了这一轮
- `break`：材料被击穿 —— 进入修补/狡辩节点，**这是主要的戏剧高潮点**
- 没有 `probe` 的选项写字符串或 `null` 即可

## 4. 回合经济与三幕节奏（以 8 回合为例）

| 回合 | 幕 | 内容 | 怀疑度预算 | 解谜 |
|---|---|---|---|---|
| 1 | 开场 | 递交材料、第一印象 | 0 → 10 | — |
| 2 | 材料审查 | 目的 / 资金 / 行程 | 10 → 30 | 30% 概率弹窗 |
| 3–5 | 材料审查 | 主战场，允许一次"被击穿 → 修补" | 30 → 55 | 击穿时必弹 |
| 6–7 | 压力追问 | 回国约束、行程细节；说谎的复利在这里到期 | 55 → 75 | 20% 概率 |
| 8 | 裁决 | 图章演出 | — | — |

**设计原则**

1. 回合是硬约束：8 回合意味着玩家最多说 8 句话。**每个选项都花掉一次机会**，所以"少说少错"是真实策略（`wait_silent` 就设计成 -3 怀疑度）。
2. 怀疑度**只升不降是错的**：好的话术要给负值（-3 ~ -8），否则玩家没有操作空间。原型里"有备而来"路线能把怀疑度从 25 压回 8。
3. 击穿必须可挽回：击穿只是把材料变废 + 加怀疑度，玩家仍能靠解谜修补出一条活路。

## 5. 话术类型与数值倾向（写作时的定价表）

| tag | 例子 | 怀疑度 | 定位 |
|---|---|---|---|
| `risk` | 主动改口径（"其实是去旅游"） | +5 起，且大概率触发矛盾 +20 | 高风险，用来盖掉不利事实 |
| `social` | 寒暄、套近乎 | +8 | 纯亏，教玩家"废话有代价" |
| `silent` | 沉默、少说 | -3 | 保守解，但换不到信息 |
| `humor` | 自嘲、玩笑 | -2 且带 `intrigue` | 情绪价值，能救场但有 `not_flags` 限用一次 |
| `bluff` | 抬身份、编人脉 | +6 但能改变话题走向 | 中期核心玩法 |
| 直接引材料 | "邀请函在您手上" | -2 ~ -5 且触发 `probe` | 最优解，前提是材料扛得住 |

## 6. 引擎 → 表现层的接口

引擎不认识"立绘"，只吐事件；Ren'Py / 终端各自渲染。

| 事件 | 载荷 | 表现层该做什么 |
|---|---|---|
| `say` | speaker, mood, text | 显示台词 + 切换立绘（`mood` 即差分 key） |
| `player` | text | 显示玩家的选择 |
| `suspicion` | delta, value, reason | 怀疑度计跳动 + 音效；数值跨段时立绘跟着换 |
| `submit` | material | 卡牌飞入桌面 |
| `probe` | material, result, pressure, flaws | `hold`：立绘平静；`break`：立绘切 `caught` + 屏幕轻震 |
| `conflict` | statement, with | ⚠ 提示 + 两张材料并排展示（把"你被抓住"讲清楚） |
| `grant` / `material_improved` | material, removed_flaw | 卡牌入栏 / 破绽划掉动画 |
| `puzzle` | id, config | **弹出模态解谜界面**，结束后回调 `apply_puzzle_result(id, solved, moves)` |
| `puzzle_result` | tier | 分档反馈（within_budget / over_budget / fail） |
| `ending` | ending, score, coverage, missing ... | 图章演出 + 结算面板 |

> **契约铁律**：解谜结果只通过 `apply_puzzle_result` 一个入口影响数值。表现层永远不直接改 `suspicion`。

## 7. 写作规范

- 一个节点一句台词 + 2–3 个选项；超过 4 个就把节点拆开。
- **每个有负面后果的选项都必须在 UI 上打 ⚠**（引擎的 `preview_conflicts()` 已能在选择前算出矛盾）。玩家可以选错，但不可以不知情。
- 不要写"是 / 不是"这种无差别选项 —— 每个选项要携带不同的信息量或代价。
- 签证官台词用「陈述 + 一个具体细节」的结构（"流水显示这笔钱是上周分三笔现金存入的"），细节越具体，压迫感越强。
- 文本量参考：8 个节点 × 3 选项 ≈ 1200–1800 字，一小时能写完一轮。

## 8. 与 Ren'Py 的对应关系

原型的 `Interview.choose(option_id)` 对应 Ren'Py 的一个 label 循环：

```renpy
label interview_loop:
    python:
        events = eng.node_events()
    call render_events(events)
    if eng.ended:
        jump verdict
    $ build_menu(eng.available_options())
    jump interview_loop
```

完整落地方式见 `docs/04-原型到Renpy落地.md`。
