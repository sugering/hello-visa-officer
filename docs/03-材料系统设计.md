# 材料系统设计

> 材料不是"道具"，是**可被质问的证据**。系统的全部张力来自两个数字：表面可信度（能骗过第一眼）与抗追问强度（能不能扛住第二眼）。

## 1. 双轴模型

| | **低抗性（<50）** | **高抗性（≥70）** |
|---|---|---|
| **高可信度（≥70）** | 高危主力：伪造流水（72 / 25）—— 递交即可能崩 | 硬通货：护照（88 / 92）、在职证明（78 / 84） |
| **低可信度（<70）** | 废物：酒店确认单（66 / 45），只能当话题引子 | 软肋：会议邀请函（62 / 70）—— 撑得住，但补不上评分 |

**设计含义**

- 真实材料给**抗性**，伪造材料给**可信度**，两者不可兼得 —— 玩家永远缺一样东西。
- 玩家的操作空间 = 用解谜把"低抗性"补成"中抗性"（`remove_flaws` 同时 +12 抗性），而不是凭空造出完美材料。
- 终局评分里抗性不直接计分，但**被击穿的材料会退出计分**，所以抗性通过"是否还活着"间接决定成败。

## 2. 材料字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，与图片文件名一致（`item_bank_statement.png`） |
| `name` | string | 显示名，会在台词与卡牌上出现 |
| `category` | enum | `identity` / `funds` / `purpose` / `ties` —— 决定终局"覆盖面"评分 |
| `source` | enum | `genuine` 真实 / `modified` 半真 / `forged` 伪造 |
| `credibility` | 0–100 | 表面可信度，终局质量分来源 |
| `robustness` | 0–100 | 抗追问强度，低于追问压力即被击穿 |
| `facts` | string[] | **材料上写着的事实**，递交后签证官即读到，参与一致性比对 |
| `flaws` | string[] | 破绽（叙事用 + 击穿时决定扣分幅度） |
| `consumable` | bool | 一次性材料，递交后从手牌移除 |

## 3. 三类来源

| source | 数值倾向 | 叙事含义 | 玩家体验 |
|---|---|---|---|
| `genuine` 真实 | 高抗性、中低可信度 | 是真的，但不够漂亮 | 安全牌，通常解决不了资金/目的这类硬问题 |
| `modified` 半真 | 中等双值 | 真的材料改过数字 | 主力工具，可被解谜优化 |
| `forged` 伪造 | 高可信度、低抗性、击穿额外 +5 惩罚 | 整份都是假的 | 高风险：第一次追问就崩，但崩了还能修补 |

## 4. 事实与矛盾（系统的核心）

两套事实被分开维护：

| 集合 | 内容 | 何时写入 |
|---|---|---|
| `recorded_facts` | 签证官**读到过**的材料事实 | 玩家 `submit` 某材料时 |
| `statements` | 玩家**嘴上说过**的话 | 选项带 `statements` 时 |

规则：

1. 任何新写入的陈述会与 `recorded_facts + statements` 全量比对；
2. 命中 `contradictions` 表 → **+20 怀疑度、置位 `caught_lying`、立绘切 `caught`、产出 `conflict` 事件**；
3. `submit` 材料时，材料事实也会反向与既有陈述比对（同样的惩罚）。

```json
"contradictions": [
  ["purpose:conference", "purpose:tourism"],
  ["funds:self_saved", "funds:company"],
  ["stay:5days", "stay:7days"],
  ["job:engineer", "job:unemployed"]
]
```

**为什么这样设计**

- 材料在"递交"那一刻才进入比对池 —— 玩家可以先把材料压在手里，等口径定下来再递（真实的签证策略）。
- 矛盾只能靠 `preview_conflicts()` 在 UI 上提前示警，不能偷偷扣分。当前原型里 `state_tourism` 这个选项在选择前就会返回
  `{"new": "purpose:tourism", "with": "purpose:conference"}`。
- `caught_lying` 是**一次性的全局污点**：终局修正从 +10 变 -15，且怀疑度 ≥ 60 时直接出局。

## 5. 追问判定

```
pressure = 30 + suspicion × 0.6
robustness < pressure  →  击穿（break）
```

| 怀疑度 | 追问压力 | 会被击穿的材料 |
|---|---|---|
| 0 | 30.0 | 伪造流水（25） |
| 20 | 42.0 | 同上 |
| 25 | 45.0 | + 酒店确认单（45，临界） |
| 30 | 48.0 | + 酒店确认单 |
| 65 | 69.0 | + 整理版流水（68）、邀请函（70，临界） |
| 70 | 72.0 | + 邀请函 |
| 90 | 84.0 | + 在职证明（84，临界） |

**击穿代价**：`10 + 5 × 破绽数 (+5 若为伪造)`

| 材料 | 破绽数 | 击穿扣分 |
|---|---|---|
| 伪造流水 | 2 | 25（含伪造 +5） |
| 酒店确认单 | 1 | 15 |
| 邀请函 | 2 | 20 |

**顶住追问**：怀疑度 -3 —— 正确引用材料是稳定正收益，鼓励"有据可依"而不是"胡编"。

> 调参要点：`30` 是"起步压力"，决定了低抗性材料在第几回合会崩。想让前期更宽松就降到 25，想让伪造材料更危险就升到 35。

## 6. 材料生命周期

```
[起始] ──→ owned ──submit──→ submitted（进入评分，事实被读到）
             │                    │
             │                    ├─ probe 击穿 ──→ exposed（退出评分，卡牌打红叉）
             │                    └─ consumable ──→ 从手牌移除
             └─ 解谜奖励 grant ──→ owned（新卡，如 bank_statement_clean）
```

三条铁律：

1. **击穿不等于毁掉**。exposed 只是不能计分，玩家仍能用手上的其他材料翻盘。
2. **消耗必须可预期**。可消耗材料在 UI 上要标"一次性"，否则玩家会在错误时机用掉。
3. **修补后是新卡**（`bank_statement` → `bank_statement_clean`），不是原地改数值 —— 这样存档、卡牌栏、回溯都好处理。

## 7. 解谜 → 材料的管线

解谜不是独立小游戏，它必须**直接改写材料数值**，否则玩家会觉得被强行打断。

三种产出：

| 产出 | 例子 | 用于 |
|---|---|---|
| **新料** | `grant: ["bank_statement_clean"]` | 击穿后的补救路线 |
| **修补** | `remove_flaws: ["bank_statement:存款日期集中"]`（抗性 +12） | 让材料扛住下一轮追问 |
| **情报** | `flags: ["seal_solved"]` 解锁对话选项 | 让玩家在对话里多一张牌 |

**奖励分档**（在 `puzzles.json` 里配置）：

| 档位 | 条件 | 效果示例 |
|---|---|---|
| `on_solve_within_budget` | 步数 ≤ 预算 | 怀疑度 -5 + 新料 + 修补 |
| `on_solve_over_budget` | 完成但超步数 | 只给新料，不给修补 |
| `on_fail` | 失败 | 怀疑度 +12，不给任何东西 |

> 关键平衡：**失败也要继续**。解谜失败只加怀疑度，绝不卡死流程 —— 视觉小说的玩家不该被小游戏锁住。

## 8. 难度旋钮

| 旋钮 | 位置 | 简单 | 标准 | 困难 |
|---|---|---|---|---|
| `round_limit` | scenario | 10 | 8 | 6 |
| `starting_suspicion` | scenario | 0 | 5 | 15 |
| `pass_threshold` | scenario | 45 | 55 | 65 |
| 解谜出现频率 | dialogue 里挂 `puzzle` 的节点比例 | 1 个 | 3 个 | 5 个 |
| 起始材料数 | scenario | 7 | 5 | 3 |
| 陷阱选项比例 | 对话写作 | 10% | 25% | 40% |
| 追问系数 | engine 的 `30 + 0.6s` | 25 + 0.4s | 30 + 0.6s | 35 + 0.8s |

**难度不该靠"数值变硬"实现，而该靠"可选择的东西变少"。** 困难关的体验是：每次开口都要赌，而不是数字更大。

## 9. 关卡设计模板

写新关卡时按这个顺序填空：

1. **目标**：玩家要骗过签证官拿到什么？（`verdict` 判定什么）
2. **软肋**：哪一类材料天然不足（资金？回国约束？目的？）→ 决定 `required_categories`
3. **起始牌**：`starting_materials`（通常 5 张，其中 1–2 张是伪造的）
4. **矛盾陷阱**：写 2–3 组 `contradictions`，让它和某个"诱人选项"绑在一起
5. **解谜插入点**：放在"被击穿"之后（修补）或"独立场景"开场（伪造）
6. **三条路线**：有备而来 / 靠嘴硬 / 手里没东西 —— 三条都要能走完并给出不同结局

### 已完成示例：`interview_01_conference`

| 项 | 值 |
|---|---|
| 回合上限 / 起始怀疑度 | 8 / 5 |
| 起始材料 | 护照、会议邀请函、银行流水（伪造）、在职证明、酒店确认单 |
| 需要覆盖 | identity 0.25 / funds 0.35 / purpose 0.40，可信度 ≥ 50 |
| 阈值 | ≥55 通过；≥40 行政审查；否则拒签；`caught_lying` 且怀疑度 ≥ 60 直接出局 |
| 解谜 | `seal_align`（3×3 灯光对齐，预算 5 步）挂在"流水被击穿"节点 |

**三条路线的实测结果**（`python run_demo.py good|bluff|bare`）：

| 路线 | 关键选择 | 怀疑度 | 总分 | 结局 |
|---|---|---|---|---|
| good 有备而来 | 递交 → 引材料 → 出示流水 → **被击穿** → 解谜修补 → 重新递交 → 提在职证明 | 8 | 108.7 | `approved` |
| bluff 靠嘴硬 | 递材料后改口"去旅游"（矛盾 +20）→ 公司报销 → 讲笑话 | 32 | 43.4 | `administrative_review`（缺 funds） |
| bare 手里没东西 | 沉默 → 改口 → 含糊 → 讲笑话 | 15 | 5.5 | `denied`（三项全缺） |

> 注意 good 路线：**被击穿一次仍然拿到通过**。这是整个系统的价值主张 ——
> 失误不是死亡，失误是"必须现在花回合去修"的账单。

## 10. 平衡检查清单

- [ ] 最强材料的抗性 ≥ 压力曲线的第 6 回合值（否则第 6 回合后无人能过关）
- [ ] 每条路线都能在 `round_limit` 内走完，且至少留 1 回合余量
- [ ] 每个 `submit` 都有非它不可的理由（避免"全都交上去"最优）
- [ ] 每个矛盾陷阱都在 UI 上可预判
- [ ] 解谜失败后仍有 ≥1 条活路
- [ ] 三种结局都能在 8 回合内达成（自动化跑 `test_engine.py` 里的路线回归）
